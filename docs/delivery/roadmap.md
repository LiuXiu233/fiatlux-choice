# FIAT LUX CHOICE 长期路线图

路线图起点：受控候选（尚未批准 V1）

规划范围：0–24 个月

原则：先降低运营负担和风险，再扩展功能；每一阶段以退出条件而不是日期强行放行

## 1. 优先级规则

每个路线图事项按以下顺序评估：

1. 是否消除数据丢失、越权、误付款、误签署或合规失控。
2. 是否每月为 1–2 人团队节省可测量的重复工作。
3. 是否改善现金、合同、义务或交付的可见性。
4. 是否有真实用户和稳定接口，而非仅有技术兴趣。
5. 是否能留在模块化单体和标准适配器内。

在前一阶段退出条件未满足时，不应为追求新功能推迟修复、恢复演练和合规复核。

## 2. 0–3 个月：冻结 V1 候选与受控试运行

### 目标

把已经完成本机 production-like 验证的候选版本，变成有不可变 Git/GitHub 证据、能在目标办公内网恢复、可审计并可由两人或单人补偿控制运行的内部系统。

## 3. 3–6 个月：低人力运营与成人教育试点

### 目标

用真实运营数据验证系统是否减少遗漏，并用一班成人小班验证教育产品。

### 交付

- 每日/每周经营摘要、逾期分级和 13 周现金预警。
- 经批准的邮件或企业协作通知适配器，保留站内为事实源。
- 为现有合规来源变更监控和复核任务接入经批准的邮件/企业协作通知；保留当前确定性协调责任人、站内通知、任务与审计作为事实源，不让外部渠道回执改写专业复核状态。
- 基于已实现的受控审计导出，增加批准的保留/销毁复核、管理层月报、风险接受到期提醒，以及现有 `lease_expired` 处置队列的超时 SLA、负责人升级、月度趋势和补偿复核报表。
- 第一个成人团队赛训或竞技基础小班，从机会、合同、交付到退款/复盘闭环。
- 课程内容版本、讲师授权、学员告知和删除期限台账。
- 公开内容到成人试点的最小漏斗：无跟踪的课程说明、年龄/适用性筛选、完整告知、人工合同、交付、退款/投诉与删除；留言不自动视为报名或营销同意。
- 真实 LLM 小范围启用：供应商审查、脱敏、预算、质量样本和停用开关。
- GitHub 只读同步：最小权限 token、速率和失败可见性。
- 会计系统 CSV/标准格式人工导入适配器，不做自动报税。

### 建议投入

| 职能 | 投入 |
| --- | --- |
| 公司负责人/运营 | 每周 1 天系统复核 |
| 全栈维护者 | 0.2–0.3 FTE |
| 教育产品负责人 | 0.3 FTE |
| 教练/内容专家 | 按班次 0.2–0.4 FTE |
| 法务、财税、安全 | 合计每月 3–5 专业人日 |

### 退出条件

- [ ] 90 天内没有因系统遗漏造成的逾期 critical 义务。
- [ ] 通知失败可见，关键通知有站内确认或人工补偿。
- [ ] 成人试点按合同完成，投诉、退款和隐私请求全部闭环。
- [ ] 至少 20 个顾问样本完成人工质量评分，越权引用为零。
- [ ] 课程贡献毛利、完成率和复购信号达到预先记录阈值。
- [ ] 公开内容没有未注明来源的结果承诺；版本到期、游戏规则变化和纠错请求均能产生复核动作。
- [ ] 月度恢复演练和权限复核按计划完成。

## 4. 6–12 个月：标准化集成与可重复增长

### 目标

只把已经重复发生且耗费人力的流程自动化，形成第二个可重复交付的教育或电竞服务产品。

### 交付

- OIDC 或企业身份接入、MFA、管理员恢复和设备会话管理。
- 自定义角色模板、临时访问、到期回收和季度权限证明。
- 合同模板、版本比较、义务提取建议和续期工作流；签署仍保持人工边界。
- 财务导入对账、发票查重和现金情景分析；不越过合法接口边界。
- 顾问评测集、提示词发布审批、成本/延迟看板和供应商切换演练。
- 工作流条件、人工暂停、显式新运行、重试/补偿和版本发布治理；任何可能已有副作用的失败都不得静默重放。
- 第二期/第三期成人课程或首个机构客户，建立讲师准入和观察机制。
- 评估是否需要独立学员门户；只有真实需求才建立最小报名、内容和反馈界面。
- 归档保留、法定销毁批准和可验证删除。
- 在备份量、合规或主机威胁达到触发阈值时，把主机文件 Ed25519 私钥迁移到经批准的 HSM/KMS/远程签名适配器；保留标准 attestation schema、密钥版本、撤销/轮换记录和离线验签能力，不把供应商成功响应直接等同于备份成功。

### 建议投入

| 职能 | 投入 |
| --- | --- |
| 产品与运营 | 0.4 FTE |
| 全栈维护者 | 0.3–0.5 FTE |
| 教育交付与内容 | 0.5 FTE 或合同制 |
| 安全/运维 | 0.1 FTE |
| 法务、财税、隐私 | 每月 4–6 专业人日 |

### 退出条件

- [ ] 至少两个产品连续两期可重复交付。
- [ ] 80% 的重复运营任务由受控工作流创建或提醒，但高风险批准仍由人完成。
- [ ] 身份、权限、提示词和工作流变更都有发布审批。
- [ ] 真实集成故障演练不会产生重复外部动作或虚假 confirmed。
- [ ] 数据保留和删除在数据库、对象存储与备份中有批准策略。
- [ ] 当前模块化单体性能满足经记录的 SLO。

## 5. 12–24 个月：按证据扩展

### 目标

在业务、团队和法规事实支持时，扩展组织、教育交付和可靠性，而不是预先引入平台复杂度。

### 可能交付

- 面向机构客户的多组织隔离、委托管理和审计包。
- 正式企业 PKI、集中身份、集中日志和受控灾备主机。
- PostgreSQL 高可用或托管方案、对象跨故障域复制和自动恢复验证。
- 独立学员门户/LMS 适配器，支持最小报名、内容、作业和反馈。
- 在专项合规审查后评估未成年人、直播、认证或职业培训；任一方向可被否决。
- 顾问检索评测、政策变化差异解释和专业复核协作。
- 对真实、稳定、合法的财税或签章接口建立专用 real adapter；仍保留人工批准和对账。
- 当拆分触发条件成立时，优先拆独立媒体处理、通知或学员门户，不拆事务紧密的核心治理模块。

### 建议投入

| 情景 | 团队建议 |
| --- | --- |
| 内部工具保持 1–2 人使用 | 0.2–0.3 FTE 工程维护加分时专业顾问 |
| 教育业务稳定增长 | 1 名教育运营/内容负责人，工程保持 0.5 FTE |
| 出现机构客户和多组织需求 | 1 名全栈、0.5 名产品运营、分时安全与合规 |
| 公网学员平台或敏感个人信息扩大 | 至少增加专职工程/运维责任，不再由单人兼职承担全部 on-call |

### 退出条件

- [ ] 新业务有收入、用户、法规和数据流证据，而不是假设。
- [ ] 威胁模型、数据保护、合同和专业意见在开发前完成。
- [ ] 目标 SLO、RPO、RTO 和容量经过负载及恢复测试。
- [ ] 团队具备实际 on-call、事件响应和供应商管理能力。
- [ ] 新服务的独立数据所有权、扩容和故障域足以支持架构拆分。

## 6. 持续治理指标

每月只看少量能推动行动的指标：

- 逾期 critical/high 义务数。
- 未完成高风险审批和缺少回执的 approved 动作数。
- 13 周最低现金余额与预测偏差。
- 开放高风险数量和平均关闭时长。
- 备份成功率、最近恢复时间、实测 RPO/RTO。
- `lease_expired` 数量、partial run 未复核时长和人工补偿完成率。
- 权限异常、失败登录和离职撤权时长。
- 顾问事实引用通过率、人工改写率、单位有效建议成本。
- 教育产品完成、投诉、退款、贡献毛利和风险事件。
- 每月系统维护人时和自动化实际节省人时。

任何指标没有负责人、阈值和动作时，不应为了“看起来完整”而加入看板。

## 7. 架构升级闸门

引入新服务、队列、数据库、实时协作、原生移动端或公网入口前，必须回答：

1. 当前系统的哪项测量指标无法满足？
2. 是否可以先通过索引、队列隔离、缓存、读模型或流程调整解决？
3. 谁长期维护新组件，故障时谁响应？
4. 备份、恢复、审计和权限如何跨新边界保持？
5. 新复杂度每月节省多少人工或产生多少收入？

没有具体答案时，继续使用模块化单体和适配器。
