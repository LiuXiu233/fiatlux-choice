# 官方来源监控策略

## 监控对象

监控 `official-sources.json` 中每个 URL，以及国家法律法规数据库同名检索结果、发布机关的政策栏目和相关附件。一个来源有正文、附件、解读和办事指南时分别保存，不用解读页面的哈希代替正文。

当前自动抓取器只接受仓库中明确登记的 9 个官方主机名，且每一跳都重新校验。只发送 `GET`，拒绝 URL 凭据、非标准端口、IP 字面量、非白名单重定向、私网/链路本地/保留地址及 IPv4/IPv6 转换地址。HTTP 地址只允许作为跳转入口，最终正文必须通过 HTTPS 获取。DNS 解析结果会在连接时固定，防止解析检查与实际连接之间被换成内网地址。

## 抓取证据

每次成功抓取在 PostgreSQL 的追加式 `compliance_source_snapshots` 中保存：组织与来源 ID、请求 URL、最终 URL、HTTP 状态、抓取时间、内容类型、`ETag`、`Last-Modified`、文件大小、原始响应 SHA-256、规范化内容 SHA-256、前一内容哈希、变更判断、最多 100,000 UTF-8 字节的规范化摘录和抓取器版本。来源主记录另保存最近成功哈希、检查/抓取时间、最终 URL、HTTP 元数据和下次自动检查时间。

自动请求总时限 15 秒、响应上限 2 MiB，并要求服务端遵守 `Accept-Encoding: identity`；意外压缩正文会失败关闭，绝不把压缩字节当成正文。HTML 会移除脚本、样式和标签并折叠空白；PDF 等二进制内容以原始字节作为规范化哈希输入。当前数据库快照保留哈希和必要摘录，不保存完整原始文件；需要原件级档案证据时，应将原始 HTML/PDF 作为受控文件单独归档并关联来源。该边界不得包装成完整网页存证。

快照记录只追加不覆盖。重定向、404、登录墙、验证码、证书错误、空正文、超限响应和压缩编码异常均生成失败状态与审计，不自动认定文件失效。

## 变更检测

1. 先比较 HTTP 元数据和原始文件 SHA-256。
2. 哈希变化后对规范化正文做结构化差异，忽略访问计数、导航、责任编辑和纯样式变化。
3. 重点提取标题、文号、效力词、公布/施行/失效日期、主体、阈值、期限、处罚和附件变化。
4. 同名新记录、修改决定、废止决定或新的实施文件优先级高于普通页面文字变化。
5. 首次成功获取会把机器状态从 `pending_fetch` 更新为 `current`，但不会把人工状态从 `pending` 改成 `reviewed`。
6. 已有内容哈希发生变化时，来源机器状态改为 `changed`、人工状态改为 `stale`、业务状态改为 `uncertain`，并在同一数据库事务创建一条高优先级人工复核任务、确定协调责任人、原子送达站内通知，并写入任务、通知与 `monitor_change_detected` 审计；不删除已完成事项和历史证据，也不会自动生成新的政策结论。
7. 人工复核人可从合规条目的“查看监控快照”读取当前组织内的分页历史，对比规范化/前一/原始响应哈希、抓取时间、HTTP 状态、类型、长度、最终地址和摘录；仍必须另开官方原文并核对适用事实，上传复核证据，再通过“登记专业复核”专用入口形成新结论。不能用通用编辑直接改 `reviewStatus`/`active`；机器哈希状态与专业复核历史始终分别展示。

## 频次

- 每周：税务发票、数据跨境、AI、互联网许可、未成年人和校外培训。
- 每月：广州最低工资、社保、公积金、办事指南和属地区许可材料。
- 每季度：公司登记、劳动、消费者、知识产权和地方性法规。
- 每半年：民法典、档案等相对稳定的中央法律法规。
- 事件触发：产品公开上线、增加未成年人、改变收费、切换模型或云服务商、发生数据事件、股东/控制权变化、员工入离职及主管机关通知。

JSON 的 `nextReviewAt` 是最迟人工复核日，不替代自动监控。每日扫描会先把到期的 `reviewed` 来源原子降级为 `stale/uncertain`，在同一事务建立立即到期的高优先级人工复核任务、指派有效 owner 作为协调责任人、送达站内通知、写 `review_expired` 审计，并强制排入一次来源检查。该状态转换只发生一次，重复扫描不会为已是 `stale` 的同一到期事件重复建任务或通知。顾问运行时还会独立要求 `nextReviewAt` 非空且晚于当前时间；即使 worker 停摆或扫描延迟，过期/无复核日来源及其关联义务、事件也只会作为缺失信息 withheld。政策临近 `expiry` 前90日、30日和7日分别提醒，并在到期后停止生成新的优惠结论。

后台使用 pg-boss 每日 `02:30`（`Asia/Shanghai`）扫描 `nextMonitorAt` 到期记录，并拆分为逐来源任务。新导入的来源按 JSON 中稳定顺序分散到导入日起 7 个每日时间桶；已有来源始终保留自己的 `nextMonitorAt`，metadata-only 重跑不会把它们重新排队。当前 73 条目录因此不会在首次启动时同时抓取，也不会因实验室或办公网统一阻断而在同一天全部进入第三次失败升级。

每个组织的一次定时扫描默认只按 `nextMonitorAt + id` 领取最早到期的 12 条，最多可通过 `COMPLIANCE_MONITOR_SWEEP_BATCH_SIZE` 在 1–250 范围内调整；查询额外读取第 13 条来判断是否仍有积压，但不会提前领取它。`monitor_dispatch` 审计保存 `batchLimit`、`dueCount`、`queuedCount` 和 `hasMoreDue`，下一次每日扫描继续处理未领取记录。当前 73 条目录的七个初始时间桶每桶最多 11 条，默认容量可在最短 7 天周期内完成首轮派发；若目录增长、旧积压或人工复核到期占用容量，值班人必须依据审计决定是否临时调高，不能用调大批次掩盖网络故障。分批不改变逐来源 pg-boss 重试、连续失败计数或第三次失败人工升级。

“合规知识库”顶部的“官方来源监控状态”是按当前登录组织实时计算的只读运营视图。它分别显示未归档来源、已到期且无有效租约的待领取来源、有效租约、首次未抓取、最近检查失败、正文变化、陈旧/过期人工复核，以及最早到期和下一次未来检查时间；这些集合可以重叠，不能相加后当作来源总数。最近批次来自本组织最新一条结构有效的 `monitor_dispatch` 追加审计；审计缺失或旧 metadata 无法通过契约校验时显示“尚无可解析记录”，不会猜测历史。

当前积压提示只由实时 `dueAvailableCount` 决定；最近批次的 `hasMoreDue` 只描述该批次发生时的事实。刷新面板不会排队、抓取、更新来源或触发专业复核。面板有 `compliance-items:read` 才可见，所有查询都按组织隔离；这些机器指标均不表示法规现行有效、适用于耀光、正文已完整归档或已经取得专业意见。

导入时按资料领域赋予 7、30、90 或 180 天的可编辑 `monitoringCadenceDays`；这是运营检查频率，不是法规效力或适用性结论。有 `compliance-items:update` 权限的人也可在合规知识库逐条点击“检查官方来源”，人工触发不受每日批次容量限制，人工触发、排队、执行和失败分别写审计。

排队前会以 `organization + source` 在数据库原子领取两小时租约并保存关联 job ID。定时扫描、重复点击和 worker 并发只能有一个领取者执行；重复人工请求返回已有在途 job，不再二次排队。worker 只处理与自己 claim token 相符的任务，成功后释放租约；失败重试保留并续期同一租约。人工在抓取期间修改来源造成版本变化时，陈旧结果会回滚且不会被误记为抓取失败或虚增 `monitoringFailureCount`。

## 失败与降级

任何抓取失败都会设置 `contentHashStatus=failed`，保存脱敏后的失败原因、连续失败次数和下一次重试时间，并写 `monitor_fail` 审计；最后一次成功哈希和快照不会被失败结果覆盖。连续第三次失败时，人工复核状态自动改为 `stale`、业务状态改为 `uncertain`，并在同一事务创建一条包含脱敏错误的高优先级人工复核任务、指派协调责任人并送达站内通知。第四次及以后连续失败不会为同一轮故障重复建任务或通知；成功抓取会把计数归零，未来新一轮第三次失败可再次升级。负责人应通过同一机关官网、国务院公报或国家法律法规数据库寻找迁移页面；不得静默改用商业转载、搜索摘要或模型记忆。

到期、正文变化和连续第三次失败创建的任务均为 `todo/high` 并立即到期。人工触发时，worker 会重新核对触发者仍是本组织有效成员、用户仍有效且仍有 `*`、`compliance-items:*` 或 `compliance-items:update` 权限，满足时才将其作为协调责任人；定时触发或触发者已停用/失权时，系统按 membership 创建时间与用户 ID 确定性选择最早加入的有效 owner。若 legacy 异常数据不存在有效 owner，任务仍会创建但保持未指派，且不会跨组织猜测接收人。协调责任人不等于专业复核人，系统也不验证其资质。

有协调责任人时，同一事务先创建 `queued` 站内通知，再由当前监控 worker 原子推进到 `sent`，分别写 `create`/`deliver` 审计；无需第二个队列投递，因此任务、通知与来源状态不会出现 outbox 半完成。任务说明保存来源 ID、标题、发布机关、官方地址、触发原因、所需人工动作及必要的脱敏错误；来源事件 metadata 使用 `escalationTaskId`、`escalationNotificationId`、`escalationAssigneeId` 和 `assignmentStrategy` 关联。重复事件不会重复建任务或通知。完成任务不会自动把来源写成 `reviewed`，更新来源也不会伪造任务完成；两项都需人工核对并分别留痕。当前仍不会自动发送邮件、企业协作消息或伪造已经联系主管机关，外部通知适配器属于后续受控集成。

## 人工确认

以下变化必须人工确认：效力状态、主体范围、税率或金额、行政许可分类、未成年人规则、数据出境阈值、处罚变化和地方窗口材料。纯排版变化可由复核人标记为非实质变更，但仍保存差异证据。
