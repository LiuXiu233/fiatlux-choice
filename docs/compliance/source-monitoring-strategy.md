# 官方来源监控策略

## 监控对象

监控 `official-sources.json` 中每个 URL，以及国家法律法规数据库同名检索结果、发布机关的政策栏目和相关附件。一个来源有正文、附件、解读和办事指南时分别保存，不用解读页面的哈希代替正文。

## 抓取证据

每次成功抓取保存：请求 URL、最终 URL、HTTP 状态、抓取时间、页面标题、机关、`ETag`、`Last-Modified`、原始 HTML/PDF、规范化文本、文件大小、SHA-256 和抓取器版本。

正文快照只追加不覆盖。附件与正文必须建立父子关系。重定向、404、登录墙、验证码、证书错误和正文显著缩短均生成异常事件，不自动认定文件失效。

## 变更检测

1. 先比较 HTTP 元数据和原始文件 SHA-256。
2. 哈希变化后对规范化正文做结构化差异，忽略访问计数、导航、责任编辑和纯样式变化。
3. 重点提取标题、文号、效力词、公布/施行/失效日期、主体、阈值、期限、处罚和附件变化。
4. 同名新记录、修改决定、废止决定或新的实施文件优先级高于普通页面文字变化。
5. 任何实质变化将相关来源、适用性结论、控制和未来日历项标为 `needs_review`，但不删除已完成事项和历史证据。

## 频次

- 每周：税务发票、数据跨境、AI、互联网许可、未成年人和校外培训。
- 每月：广州最低工资、社保、公积金、办事指南和属地区许可材料。
- 每季度：公司登记、劳动、消费者、知识产权和地方性法规。
- 每半年：民法典、档案等相对稳定的中央法律法规。
- 事件触发：产品公开上线、增加未成年人、改变收费、切换模型或云服务商、发生数据事件、股东/控制权变化、员工入离职及主管机关通知。

JSON 的 `nextReviewAt` 是最迟人工复核日，不替代自动监控。政策临近 `expiry` 前90日、30日和7日分别提醒，并在到期后停止生成新的优惠结论。

## 失败与降级

连续三次抓取失败后创建人工任务，通过同一机关官网、国务院公报或国家法律法规数据库寻找迁移页面。不得静默改用商业转载、搜索摘要或模型记忆。无法确认时保留最后已验证快照，状态改为 `needs_review`，相关高风险自动化停止。

## 人工确认

以下变化必须人工确认：效力状态、主体范围、税率或金额、行政许可分类、未成年人规则、数据出境阈值、处罚变化和地方窗口材料。纯排版变化可由复核人标记为非实质变更，但仍保存差异证据。
