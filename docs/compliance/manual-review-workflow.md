# 合规知识人工复核流程

## 系统状态

研究阶段的 `discovered`、`source_verified` 只用于资料整理，不是应用数据库状态。应用把三个维度分开保存：

- 来源生命周期 `status`：`draft`、`active`、`superseded`、`repealed`、`uncertain`。
- 专业复核状态 `reviewStatus`：`pending`、`reviewed`、`stale`。
- 自动监测状态 `contentHashStatus`：`pending_fetch`、`current`、`changed`、`failed`。

自动抓取成功或哈希一致不等于专业复核。通用新建和编辑接口不能把来源提升为 `reviewed`，也不能写入 `active`、`superseded` 或 `repealed` 的确定生命周期；只有专用的证据型专业复核动作可以。已复核来源的标题、机关、URL、法域、摘要、适用条件、来源元数据或内容/元数据哈希被普通编辑后，会自动降为 `stale+uncertain`。

## 来源复核

复核人应检查官方域名和机关、正文标题、文号、公布与施行日期、效力状态、修改或废止关系、附件完整性及正文哈希。国家法律法规数据库记录应保留 `bbbs`；部门和地方网页应保存页面快照与最终跳转 URL。

来源复核通过后，只能确认“这是当前官方来源”，不能直接创建对公司的确定义务。

## 适用性复核

适用性复核必须选择一条来源版本，并引用有日期的公司事实。系统要求逐条登记：复核人姓名、专业角色、所在机构或内部组织、胜任依据、同组织已完成上传的证据文件、对耀光的适用条件、复核摘要、缺失信息、结论、来源生命周期、下次复核日和本次登记原因。即使没有已知缺失，也必须明确填写，不能用空值冒充完整判断。

结论只能是：

- `applicable`：在已记录事实和条件下适用；
- `not_applicable`：已核对后不适用；
- `changes_required`：需要补改控制或资料后再复核；
- `insufficient_information`：事实不足，不能形成确定结论。

前两类必须同时选择 `active`、`superseded` 或 `repealed` 的来源生命周期；后两类只能保持 `uncertain`。下次复核日必须晚于登记时点且不超过 366 天。缺少决定性事实时必须选择 `insufficient_information`，不得让模型补全事实。

## 在系统中登记

1. 先在“文件”上传真实复核意见、工作底稿或已核对材料，确认状态为 `uploaded`。
2. 在“合规知识库”打开目标来源的“登记专业复核”，不要使用通用编辑表单。
3. 核对页面显示的当前来源版本，完整填写上述字段并选择证据文件。
4. 提交时 API 在事务中锁定来源、校验 `expectedVersion`、组织、文件状态和复核期限；并锁定当时的来源版本、内容哈希、元数据哈希和站内登记账号。
5. 成功后查看“专业复核记录”。每次记录追加到 `audit_events`，动作是 `professional_review`，不会覆盖旧意见。

来源并发变化会返回 409，必须重新读取后再判断。通用 POST/PATCH、seed JSON 或数据库中遗留的 `reviewed` 字样都不能补造专业 provenance；旧记录没有完整复核人、机构、胜任依据、缺失信息、证据、站内登记人和版本时，顾问会失败关闭。

当前来源或历史复核审计引用过的证据文件都不能归档。需要更正意见时上传新证据并登记一条新复核；不得删除旧文件或改写旧审计。

## 控制与日历复核

只有具备完整 provenance、仍在复核期内且结论为 `applicable` 的来源，才能让其关联义务或日历作为顾问确定性上下文。`not_applicable` 可以作为该来源本身的可审计结论，但不能支持关联义务成为确定事实。每个日历项仍应保存来源、期限表达式、生成时间、责任人和履行证据要求。

税务申报日、地方动态标准和按事实计算的期限必须在每个期间重新实例化。系统生成的日期由人工确认后才成为正式日历。

## 重大事项会签

以下事项须在执行前取得明确人工批准：银行付款、税务申报、发票红冲、合同正式签署、合同终止、人事处分、关键权限修改、对外法律承诺、数据出境申报、未成年人产品上线和行政许可申请。

一人公司可以使用自我审批，但须输入明确确认语句、说明无法分离职责的原因，并保留时间、身份、拟执行内容和外部系统结果。涉及重大合同、劳动争议、税务处理、跨境数据或许可分类时，应引入外部中国专业人员。

## 模型参与边界

模型可以抽取条款、比较版本、列出缺失事实、起草摘要和建议动作。模型不得自行把条目标记为 `reviewed`，不得伪造主管机关答复，不得将网页可访问解释为现行有效，也不得执行外部法律或财务操作。

人工修改模型结论时，必须保存修改前后内容、修改人、理由、关联来源和模型运行 ID。
