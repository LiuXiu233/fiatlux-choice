# 合规知识人工复核流程

## 状态

1. `discovered`：发现候选来源，尚未核验官方性。
2. `source_verified`：已核对官方机关、标题、文号、日期、版本和效力线索。
3. `pending`：已入来源目录，等待专业人员复核；当前 JSON 条目均处于此状态。
4. `reviewed`：复核人确认来源版本、摘要、适用条件和排除条件准确。
5. `needs_review`：来源变化、公司事实变化、复核过期或存在冲突。
6. `superseded` 或 `repealed`：旧版本保留但不再作为当前依据。

来源状态和内部复核状态必须分列。例如法规可以是 `status=effective` 且 `reviewStatus=pending`。

## 来源复核

复核人应检查官方域名和机关、正文标题、文号、公布与施行日期、效力状态、修改或废止关系、附件完整性及正文哈希。国家法律法规数据库记录应保留 `bbbs`；部门和地方网页应保存页面快照与最终跳转 URL。

来源复核通过后，只能确认“这是当前官方来源”，不能直接创建对公司的确定义务。

## 适用性复核

适用性复核必须选择一条来源版本，并引用有生效日期的公司事实。复核记录至少包含：适用主体、业务行为、地域、产品角色、阈值、例外、事实证据、分析、缺失信息、结论、置信度和复核到期日。

结论只能是 `applies`、`does_not_apply`、`partially_applies` 或 `insufficient_facts`。缺少决定性事实时必须选择 `insufficient_facts`，不得让模型补全事实。

## 控制与日历复核

只有 `reviewed` 的来源与适用性结论才能映射到义务、风险、审批或合规日历。每个日历项应保存来源版本、适用性记录、期限表达式、生成时间、责任人和证据要求。

税务申报日、地方动态标准和按事实计算的期限必须在每个期间重新实例化。系统生成的日期由人工确认后才成为正式日历。

## 重大事项会签

以下事项须在执行前取得明确人工批准：银行付款、税务申报、发票红冲、合同正式签署、合同终止、人事处分、关键权限修改、对外法律承诺、数据出境申报、未成年人产品上线和行政许可申请。

一人公司可以使用自我审批，但须输入明确确认语句、说明无法分离职责的原因，并保留时间、身份、拟执行内容和外部系统结果。涉及重大合同、劳动争议、税务处理、跨境数据或许可分类时，应引入外部中国专业人员。

## 模型参与边界

模型可以抽取条款、比较版本、列出缺失事实、起草摘要和建议动作。模型不得自行把条目标记为 `reviewed`，不得伪造主管机关答复，不得将网页可访问解释为现行有效，也不得执行外部法律或财务操作。

人工修改模型结论时，必须保存修改前后内容、修改人、理由、关联来源和模型运行 ID。
